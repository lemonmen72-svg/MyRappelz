# Ноутбук как исполнитель проверок и сборок

Ноутбук Максима (Windows 11, WSL2 Ubuntu 24.04) — исполнитель GitHub Actions с меткой `laptop`.
Куда идут «Проверка кода» (автотесты) и «Сборка APK» — решает `.github/runner.txt`:
`laptop` — на ноутбуке, `github` — на серверах GitHub (ночью, когда ноутбук выключен). Меняет Claude коммитом.
Скриншоты и замер нагрузки — всегда на GitHub. Правило «APK только по команде Максима» не меняется.

## Установка (один раз)
1. PowerShell **от имени администратора**, в папке репозитория:
   `powershell -ExecutionPolicy Bypass -File tools\laptop\install.ps1`
2. Попросит перезагрузку — перезагрузить и запустить снова.
3. Попросит ключ — открыть страницу, которую покажет скрипт, скопировать ключ из строки `--token КЛЮЧ`.
4. В конце: «Готово». Написать Claude «исполнитель установлен».

Дальше ничего делать не нужно: при входе в Windows WSL и исполнитель стартуют сами (ярлык
`dark_pact_runner.vbs` в автозагрузке), исполнитель сам забирает задания, логи видны на GitHub.
Собранный APK сам ставится на телефон, подключённый по USB (нужна «Отладка по USB»; adb — из Android Studio).

## Что внутри
- `install.ps1` — WSL2 и Ubuntu, `.wslconfig` (16 ГБ, 4 потока, без засыпания), автозапуск, вызов `setup_wsl.sh`.
- `setup_wsl.sh` — systemd, пакеты, Java 17, Android SDK (`/opt/android-sdk`: платформа 34, build-tools 34.0.0,
  NDK 23.2), пользователь `runner`, исполнитель в `/home/runner/actions-runner` как служба systemd.
- Рабочая папка исполнителя не чистится между запусками: импорт Godot (`.godot`) остаётся — повторные проверки
  быстрее; первый импорт на i3 — 30–60 минут.

## Если что-то не так
- Проверить службу: `wsl -d Ubuntu-24.04 -u root -- bash -c "cd /home/runner/actions-runner && ./svc.sh status"`.
- Переустановить: запустить `install.ps1` ещё раз (сделанное пропускается).
- Убрать исполнитель: GitHub → Settings → Actions → Runners → удалить; `wsl --unregister Ubuntu-24.04`;
  удалить `dark_pact_runner.vbs` из папки автозагрузки.
