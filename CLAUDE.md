# Проект: своя 3D-игра в духе Rappelz Online (Android)

Стартовый контекст для сессий Claude Code. Язык общения с пользователем (Максим): русский.

## ⛔ Главное правило: сборка APK только по команде
- **Не собирать APK без прямой команды Максима.** Это касается и запуска workflow «Сборка APK»
  (`.github/workflows/android-apk.yml`), и локального экспорта Godot под Android, и создания релизов.
- Команда должна быть явной («собери APK», «сделай релиз» и т. п.) и относится только к одной сборке.
  Разрешение на прошлую сборку не переносится на следующую.
- Без команды можно: править код, коммитить, пушить, запускать автотест (workflow «Проверка кода»).
- Workflow сборки APK запускается только вручную: кнопкой Run workflow, пушем тега `v<версия>`
  или изменением версии в `android/release_version.txt`. Других триггеров (обычный push, PR, расписание) у него быть не должно.
- Claude не может нажать Run workflow (нет прав у интеграции) и пушить теги (прокси сессии),
  поэтому по команде Максима поднимает версию в `android/release_version.txt`, коммитит и пушит.
  Без команды этот файл и теги `v*` не трогать.

## Идея
Максим делает свою игру, похожую на Rappelz Online, под Android.
Главный ориентир по механикам: официальный сайт игры https://rz.gamexp.com/ — на него опираемся почти во всём
(классы, расы, система питомцев, умения, баланс, интерфейс, устройство мира).
Но это не копия: графику, модели, музыку, тексты, названия, персонажей и карты Rappelz использовать нельзя
(авторское право и товарный знак). Берём механики и общую структуру, всё содержимое своё и оригинальное.

## Решения, принятые с пользователем
- Платформа: Android. Движок: Godot 4.3 (GDScript), рендерер GL Compatibility. Графика: 3D.
- Начинаем офлайн, без сервера и мультиплеера. Приоритеты: бой, питомцы, мир.
- Сервер и мультиплеер: позже, когда основа станет играбельной.

## Структура репозитория
Проект Godot лежит в корне репозитория (плоская структура).

### Ядро (общее, меняется только согласованно)
- `project.godot`: настройки, автозагрузка `Game`, горизонтальная ориентация, касания ↔ мышь, ETC2/ASTC.
- `game_state.gd` (автозагрузка `Game`): персонаж (имя, раса, класс, уровень, опыт, золото; при загрузке
  любой другой класс переводится в Наёмника, сообщение — `Game.load_note`), сумка
  (`Inventory`), надетое оружие `Game.weapon`, умения героя `Game.hero` (JP, изученные, включённые, кнопки),
  коллекция питомцев `Game.pets` (записи-словари), `active_pet`, задания (`quests_active` с прогрессом целей,
  `quests_done`, `quest_tracked`; ключ `quests` в сохранении, у старых сохранений — пусто), сохранение `user://save.json`.
- `main.tscn` + `main.gd`: создание персонажа → мир, игрок, звери по слотам, модули, кнопки HUD,
  маршрутизация действий HUD в модули (`handle_action`), события убийства зверя (`on_mob_killed`), автосохранение.
- `hud.gd`: джойстик, круглые кнопки (`add_button`, `is_held`, `set_cooldown`, `set_blocked`), окна (`create_window`),
  панели игрока (HP, MP, опыт), питомца и цели, сообщения; меню «Герой / Питомцы / Сумка / Задания / Настройки»
  (кнопки меню помельче — `MENU_FONT`, панель цели сдвигается левее меню); `add_blocker` — элементы поверх мира
  (трекер заданий), касание по ним не вращает камеру. Размеры — из `UiScale` (числа в коде даны для «Среднего»):
  `apply_ui_scale()` перестраивает HUD сразу (сигнал `scale_changed` — трекер), окно держится по центру и в экране.
  Кнопки — значками (`set_button_icon`, `set_button_count`, `button_icon`; подпись остаётся в `button_text`):
  умения — значок умения, «Атака» — надетое оружие, «Зелье» — зелье с числом, «Приручить» — карта вида цели,
  «Говорить»/«Торговец» — рисунки (`main.gd`: `BUTTON_ICONS`, `refresh_skill_buttons`, `refresh_tame_icon`);
  перезарядка — тёмный сектор, чужое оружие — красная метка. Справа от полосок HP игрока, питомца и цели —
  значки эффектов (`status_row(...)`), касание — подпись.
- Значки и эффекты: `icon_view.gd` (`IconView`: круглый значок по спецификации `path`/`item`/`shape`/`glyph` —
  общий для кнопок и эффектов; `hero_skill`, `pet_skill`, `item`; маска круга, сектор `set_sector` от 12 часов по
  часовой, кольцо, число), `status_effects.gd` (`StatusEffects`: реестр эффектов сущности — `Player.effects`,
  `Pet.effects`, `Mob.effects`; `add(id, сек, info)` при наложении, `sync(id, поле-таймер)` каждый кадр — логика
  эффектов остаётся в полях сущностей; `sync_toggles` — переключаемые без таймера; `version` растёт только при смене
  набора), `status_row.gd` (`StatusRow`: ряд значков, рамка зелёная — баф, красная — дебаф, золотая — переключаемое,
  истёкшая доля — тёмный сектор по часовой, не помещаются — «+N»; узлы переиспользуются, каждый кадр — только сектор).
  Эффекты: у героя «atk» (Боевой клич, «Зов охотницы»/«Боевой рог» питомца), «speed», «guard» (Щит света, защита
  питомца), «shade» (Танец теней), «toggle:<id>» — переключаемые героя, «pet:<id>» — «Узы» питомца; у питомца
  «toggle:<id>»; у зверя stun/sleep/fear/slow/blind/miss/vuln/weak/taunt и «dot:<умение>» (методы `Mob.stun(…, src)`
  и т. п. принимают источник `StatusEffects.source_*`). Зелья мгновенные — эффекта нет. Тест `tests/test_status_icons.gd`.
- `ui_scale.gd` (`UiScale`): масштаб интерфейса — единая точка настройки размеров: шрифты (`FONT` 17 темы,
  `FONT_TITLE` 22, `FONT_NAME` 20, `FONT_HEAD` 17, `FONT_TEXT` 15, `FONT_BODY` 14, `FONT_SMALL` 13, `FONT_TINY` 12),
  `BUTTON_H` 44, `TAB_H`, `PAD`, `GAP`, скругления, надписи в мире (`WORLD` = 0.66 прежних). Настройка «Размер
  интерфейса» Мелкий / Средний (по умолчанию) / Крупный = ×0.87 / 1 / 1.15, `user://settings.cfg` секция `[ui]`.
  Пользоваться: `UiScale.fs(UiScale.FONT_TEXT)`, `UiScale.px(44)`, `UiScale.v2(x, y)`, размер окна в
  `create_window` — база «Среднего» (окна до ~1090×600, чтобы «Крупный» влезал в 1280×720). Тест `tests/test_ui_scale.gd`
  (при каждом размере кнопки HUD не перекрываются, все окна и экран создания помещаются в 1280×720).
- `util.gd`: материалы, поиск ближайшего, тело зверя из коробок, всплывающий текст, тема UI `Util.ui_theme()`
  (размеры по `UiScale`, `refresh_theme()` — после смены размера).
- `inventory.gd`: сумка (id предмета → количество) и её раскладка по ячейкам (`Inventory.CAPACITY` = 40).

  без анимаций делает: меш ~7 тыс. треугольников, реальный размер (высота в `CREATURES`), морда в +Z, ноги на y = 0,
  понятные имена костей (Root, Hips, Chest, Neck*, Head, Tail*, LegFL1…/LegL1…, Wing*), процедурные клипы
  Idle/Walk/Run/Attack/Hit/Death/Cast (корень по X/Z на месте), `assets/creatures/creatures.json` — размеры, скорости шага
  и бега без проскальзывания, длины клипов, момент удара (`attack_hit_time`) и умения (`cast_time`), роли костей.
  Новый зверь или стадия эволюции: запись в `CREATURES` в скрипте (высота, стиль «cat»/«turtle»/«bird», шаг; стадия —
  `stage_cfg(вид, высота, …)`), затем `python3 -I tools/prepare_creatures.py <id>=<файл.glb>` (`--check` — только
  проверка готовых, `--preview <папка>` — картинки). Высота модели стадии — «база» (объём как у 1-й стадии при масштабе 1),
  крупнее на старших стадиях её делает игра (`PetData.stage_scale`). Неудобные скелеты Meshy: роли костей ищутся сами
  (лишняя нога-копия убирается, уши — самая высокая боковая ветка головы, ноги при хвосте на земле — парные концы
  сбоку); поправки в конфиге — `ground_fit`, `foot_rigid`, `toe_tip`, `ground: "feet"` (описаны в шапке `CREATURES`).
  Летающие рыбы — стиль «fish» (`FISH_CREATURES` в скрипте, отдельные функции `fish_*`): размер по длине (`length`),
  роли костей своим поиском (ось нос → хвост: Root, Body, Front*, Head, Snout*, Back*, Tail*; плавники FinL/FinR*,
  Dorsal*, Ventral*, Mouth*), клипы — волна по телу, взмахи плавников, рывок-укус, Death — переворот набок и падение.
  Высота парения (`hover`, ось тела ≈ 1.45–1.55 м — уровень головы героя) зашита в модель: поза покоя и все клипы,
  кроме Death, висят в воздухе; в `creatures.json` у рыб `height` — верх модели над землёй, `hover`, `body_height`.
  Двуногие (анатемы) — стиль «biped» (`BIPED_CREATURES`, `BIPED_CLIPS`, функции `biped_*`, `BipedRetarget`): роли костей
  гуманоида Meshy (Root, Hips, Spine*, Chest, Neck, Head, HeadEnd, Shoulder/ArmX1/ArmX2/HandX, LegX1…), клипы не
  процедурные — Quaternius UAL (CC0) переносятся на скелет как у героя (`tools/retarget_animations.py`): руки — к T-позе
  библиотеки, ноги ящера остаются своими («пятка» высоко), опорная стопа не скользит (IK бедро + голень), Death — лёжа
  на земле; скорость шага/бега — по опорной стопе. Сборка: `python3 -I tools/prepare_creatures.py --ual1 <UAL1_Standard.glb>
  --ual2 <UAL2_Standard.glb> anathema=<…> anathema_blade=<…> anathema_chief=<…>`; в `creatures.json` у них `"kind": "biped"`.
  Кентавр — стиль «centaur» (`centaur_rig`, `CentaurCtx`, `centaur_clips`; нужен ещё scipy): у Meshy конская часть без
  костей передних ног — ноги (4 связные части меша у земли, суставы по высоте), корпус (Root, Spine1, Chest), хвост
  и кость копья `Spear` (дочь кисти правой руки) строятся по геометрии меша, человек (Waist, Torso*, Neck, Head,
  ArmL*/ArmR*) — кости и веса Meshy; ноги — тот же IK, шаг четырёхтактный, бег — галоп, атака — выпад копьём,

  упрощение — `"simplify": "welded"` (упрощение по сваренным позициям). В `creatures.json` — `bones.spear/torso/arms`.

## Механики (ориентир: гайды rz.gamexp.com, своё оформление)
- Расы: Люди (Воин, Следопыт), Светлые эльфы (Страж, Жрец), Тёмные эльфы (Наёмник — id `assassin`, Чернокнижник).
- **Герой игрока пока всегда тёмная эльфийка-Наёмник** (решение Максима): на экране создания остальные расы и классы
  видны, но затемнены («скоро»); старые сохранения с другой расой/классом при загрузке (`Game.from_dict`) переводятся
  в Наёмника — уровень, опыт, золото, сумка и питомцы сохраняются, выдаётся набор оружия и надеваются парные мечи,
  JP — как будто копились с 1 уровня (не меньше прежних), при входе — сообщение. Код других классов не удалён
  (их проверяют автотесты: `new_character` принимает любой класс).
- Характеристики героя — те же 7 статов, что у питомцев (Сила, Выносливость, Ловкость, Интеллект, Мудрость,
  Меткость, Удача; `HeroStats`, формулы `Stats`), из них HP, MP, физ./маг. атака (клинки — от Силы, арбалет — от
  Меткости и Ловкости) и защита, точность (обычная атака по зверю намного выше уровнем может промахнуться), уклонение,
  крит, скорость атаки, восстановление HP; поверх — оружие и умения древа. Окно героя (вкладка «Герой») показывает
  7 статов и боевые показатели, как окно существа.
- Редкости зверей и питомцев (по возрастанию): «Базовый» `common`, «Обычный» `uncommon`, «Редкий» `rare`,
  «Уникальный» `unique` (`MobData`: `RARITY_NAMES`, ранг `RARITY_TIER`, цвет подписи `RARITY_COLORS`, тир карты
  `CARD_TIER_BY_RARITY`). Сила редкости — один множитель `MobData.RARITY_POWER` (1.0 / 1.15 / 1.3 / 1.5; поле вида
  `power` его заменяет — у стража 1.0, числа подобраны вручную): у зверя мира HP, атака, опыт (`Mob.setup`) и золото
  (`Economy`), у питомца HP, атаки, лечение и защиты (`PetStats.derived`). Новый вид другой редкости — одно поле
  `"rarity"` в `MobData.TYPES`.
- **На острове только существа Максима** (модели из файлов, решение Максима): пантера, черепаха, фазан, волк,
  летающие рыбы, анатемы. Кабан и каменный страж (модели из примитивов) в мире больше не появляются — их зоны заселены
  фазанами и волками (луга новичков 1–2 ур., южные поля, Светлая роща), логово стража — вожаком анатем; данные кабана
  и стража в `MobData`/`PetData` и запасные модели остались для совместимости. Декоративных овец в загоне тоже нет
  (модель овцы из примитивов — `PoiModels.sheep_*` — в запасе, Максим может сделать свою).
- Звери: Пантера (маг), Черепаха (танк), Фазан (лекарь) — «Базовые»; Волк — «Обычный» (решение Максима:
  сильнее базовых, приручается и призывается; боец — «существо ловкости»). Пантера,
  черепаха, фазан и волк — модели из файлов (`CreatureAsset`; запасные модели из примитивов остались); заменили
  медведя, искрожука и фею (старые сохранения переводятся при загрузке: bear→panther, sparkbug→turtle, fairy→pheasant,
  трофеи тоже). Дикие звери в мире — всегда модель 1-й стадии.
- Кентавр `centaur` — «Редкий» (решение Максима: сильнее базовых и «Обычного» волка, ×1.3), боец-копейщик (Kentauros
  вики: физический урон вблизи; статы — таблица вики, Сила главная, без обмена). Стадии «Резвое копыто», «Степной
  копейщик», «Громовой табунщик» (модели `centaur`, `_2`, `_3`, питомец — scale 0.75, ростом с героя). Дикий — 9 ур.,
  зона «Восточные равнины» (9–10 ур., 3 шт.). Карта фиолетовая (35 %), только выпадает из кентавра (3 %); трофеи
  «Наконечник копья», «Конский волос». 18 умений (свои: «Двойной выпад», «Пронзающий удар», «Топот копыт», «Узы степи»,
  «Боевой рог», «Копейный шквал», «Сокрушающий вихрь» + общие); новое ослабление зверя `weaken` (`Mob.weaken`: удары
  слабее на долю 10 с). Справка — `tools/rappelz_pet_reference.md` («Кентавр»), тест `tests/test_centaur.gd`, кадры 55, 58.
- Анатемы — человекоподобные ящеры с костяными клинками на предплечьях (не приручаются, вида питомца нет, карт нет):
  Анатема `anathema` (6 ур.), Анатема-рубака `anathema_blade` (8 ур.), Вожак анатем `anathema_chief` (10 ур., «Редкий»,
  главный враг логова у пещеры вместо стража, роняет зеркальную карту). Физический ближний бой: высокая атака, частые
  удары (`MobData` `attack_cd` → `Mob.attack_every`, 1.0–1.1 с вместо 1.3), низкая защита (`defense` 0.7–0.8 →
  `Mob.damage_taken` = 1 / защита: по ним проходит в 1.25–1.4 раза больше урона, у прочих зверей защита 1.0). Зоны:
  Западные скалы (6–7), Северо-восточный обрыв (7–8), Юго-восточный мыс (8–9), подступы к логову (8–9), логово (10).
  Трофеи «Чешуя ящера», «Костяной клинок», «Шип вожака» (значок `spike`). Тест `tests/test_anathema.gd`, кадры 56–57.
- Летающие рыбы (`flying: true`, не приручаются, вида питомца нет): Летучий зубан
  `flyfish` (5 ур.), Рыба-парусник `flyfish_sail` (7 ур.), Змеекрыл `flyfish_drake` (9 ур., редкий) — парят на уровне
  головы героя, падают на землю только после смерти; живут у реки и пруда (зоны `fish_*` острова, ур. 4–10); трофеи
  «Летучая чешуя», «Плавник-парус», «Гребень змеекрыла». Снаряды и дуги ударов целятся в `Mob.aim_point()` /
  `mid_point()` (у парящих — на высоте `hover_y`). Тест `tests/test_flyfish.gd`.
- Приручение — по системе карт существ (как в руководстве по питомцам rz.gamexp.com, тексты свои). Приручаются
  пантера, черепаха, фазан, волк и кентавр; **рыбы, анатемы, кабан и каменный страж — нет** (`tameable: false`, карт у них нет,
  на панели цели фиолетовый значок, «Приручить» — «Этого зверя нельзя приручить»). У приручаемого вида своя
  карта: пустая `card_<вид>` (стопка до 20), с душой `card_<вид>_soul` (по 1 в ячейке), тип предмета `card`.
  Тир карты = цвет (`ItemData.CARD_TIERS`, тир вида — `MobData.card_tier`, по умолчанию по редкости зверя): базовая
  коричневая («Базовые»: пантера, черепаха, фазан), обычная синяя («Обычные»: волк; внутренний ключ тира `rare`),
  редкая фиолетовая («Редкие»: кентавр; ключ `special`), уникальная жёлтая («Уникальные»). Шанс успеха по тиру (`Taming.CHANCE`):
  70/45/35/25 %. Значки `card_wolf*.png` — с синей рамкой. Где брать: карты пантеры, черепахи, фазана (25 зол.) и зеркальную карту `mirror_card` (60 зол.) продаёт
  Учитель Кирк в центре города (у торговца карт нет); карта волка выпадает из волков (4 %), кентавра — из кентавров (3 %), зеркальная — ещё из пантер,
  фазанов, черепах, змеекрылов и вожака анатем (в «где взять» — только звери, что водятся на острове, `Taming.lives_in_world`). Подарка карт новому герою нет (стартовых 50 зол. хватает на две карты у Кирка).
  Процесс: с пустой картой вида в сумке «Приручить» на цель (без карты — «Нужна карта существа: <вид> — продаётся у
  Учителя Кирка в центре города / выпадает из …»), метка, зверя победить. Успех — пустая карта становится картой с душой (в ту же ячейку;
  в полной сумке — сверх вместимости, ничего не теряется), неудача — карта ломается, а если в сумке есть зеркальная
  карта — ломается она. Формирование: «Сформировать» в карточке карты с душой в сумке или в блоке «Формирование» окна
  «Питомцы» — существо 1-го уровня в коллекцию (до 6, иначе «Коллекция полна»; приручать при полной коллекции можно).
  Описание карты в сумке: вид и роль, где водится (зоны и уровни острова), тир и шанс, где взять, что делать.
  Панель цели: значок приручения слева от полоски HP — зелёный (можно, карта в сумке), жёлто-серый (нужна карта),
  фиолетовый (нельзя, `tameable: false`) — и квадратик цвета тира. Старые сохранения: кристаллы души переводятся
  (`ItemData.RENAMED`, `LEGACY_GOLD`): базовый → зеркальная карта, редкий → зеркальная карта + 30 зол., древний →
  зеркальная карта + 100 зол.; карты кабана и стража (`card_boar*`, `card_golem*`) из прошлой версии → зеркальные карты.
  Питомцы-кабаны и стражи из старых сохранений при загрузке (`Game.from_dict`, `Game.RETIRED_PETS`) становятся волками
  и черепахами: уровень, опыт и своё имя сохраняются (имя-стадия — по новому виду), JP за умения, которых у нового вида
  нет, возвращаются (`Game.retired_refund`), сообщение — в `Game.load_note`. Вид кабана и стража в `PetData` остался
  (питомец, добавленный кодом, призывается). Коллекция до 6 питомцев, призван один.
- Питомцы: роли (танк, боец, маг, лекарь), 3 стадии эволюции, команды «Атакуй» / «За мной», воскрешение свитком.
  Модель стадии: у пантеры, фазана, черепахи и волка на 2-й и 3-й стадии своя модель `<вид>_2` / `<вид>_3`
  (`CreatureAsset.model_for`; питомец, превью в окне существа; при эволюции модель пересобирается), без оттенка
  текстуры и без процедурного нимба/сияния — только самоцвет роли над головой. Нет файла стадии — модель 1-й стадии
  с украшениями стадии (`CreatureAsset.decorate`, `CreatureModels.decorate_pet`). Размер стадии — `PetData.stage_scale`.
  Подпись над питомцем — `Pet.LABEL_PX` (0.62) от подписи зверя: питомец всегда у камеры, крупная подпись мешала.
- Характеристики питомца: Сила, Выносливость, Ловкость, Интеллект, Мудрость, Меткость, Удача (таблицы вики,
  уровень вики = наш × 1/0.3; пантера-маг: Сила ↔ Интеллект, фазан-лекарь: Меткость ↔ Мудрость, волк-боец
  «существо ловкости»: Сила ↔ Ловкость — Ловкость главная), из них HP, MP,
  атаки и пр. (`PetStats.derived`). У питомца есть MP (полоска в HUD) и его восстановление.
- Умения питомца: изучаются за JP в окне существа (кнопка «Подробнее» в «Питомцах», «Существо» у панели питомца, C).
  JP: 2 у нового + 3 за уровень опыта (копятся за убийства). До 15 ур. умения: 1–5 на 1-й стадии, 6–10 на 2-й,
  11–15 на 3-й; требуемый уровень вики × 0.3; пререквизиты. Активные применяет ИИ (урон от главной атаки роли,
  MP, перезарядка; оглушение, замедление, морок, уязвимость, промахи зверя), переключаемые («Узы …», «Дерзкий вызов»)
  включаются в окне и тратят MP раз в 10 с, пассивные — всегда. Запись питомца: `jp`, `jp_part`, `skills`, `toggles`, `mp`.
- Наёмник (≈ Strider, переходная профессия): три вида оружия сразу — парные кинжалы, парные мечи, арбалет (предметы
  `type: "weapon"`, стартовый набор в сумке, надевается в окне героя или кнопкой «Надеть» в сумке; старые сохранения —
  парные мечи). Оружие меняет атаку (ближний бой / болты), дальность, скорость, урон и модель (клинки в обеих руках,
  арбалет на изготовку — клипы `Sword_Slash_B/C`, `Crossbow_Idle/Shoot` из Quaternius UAL).
  Умения строго привязаны к оружию (`weapon`: "blades" / "crossbow" / "" — общие): с чужим оружием кнопка HUD
  затемнена с подсказкой, умение не применяется, оружейные переключаемые выключаются при смене оружия, пассивки
  владения действуют только со своим оружием; изучать заранее можно.
- Умения героя: изучаются за JP героя в окне героя (5 у нового + 10 за уровень, по долям за убийства; к 15 ур. —
  примерно половина древа; старые сохранения — как будто копились с 1 ур.). Требуемый уровень = уровень профессии
  вики × 0.3. Активные тратят MP (у Наёмника есть MP — полоска в HUD), переключаемые — MP при включении и раз в 10 с.
  4 кнопки умений в HUD (`skill1…skill4`, клавиши 1–4), назначение — «На кнопку 1–4» в карточке умения.
  Запись `Game.hero`: `jp`, `jp_part`, `skills`, `toggles`, `slots`.
- Древо умений (`SkillTree`): ярусы по требуемому уровню сверху вниз (соседние сливаются, если не помещаются),
  линии пререквизитов, уровень мелко в углу, доступные подсвечены, недоступные затемнены; касание — карточка.
- Значки умений: героя — `assets/icons/skills/<id>.png`, питомцев — `assets/icons/pets/<вид>/<id умения>.png`
  (PNG 128×128 с прозрачными углами; у видов общие id, но картинки свои). Нет файла — кружок с буквой.
- Значки предметов: `assets/icons/items/<id предмета>.png` (PNG 128×128 с прозрачными углами, грузить только через
  `load()`/`ResourceLoader`, не `Image.load_from_file` — иначе в APK не найдётся). Нет файла — процедурный значок
  `ItemIcon` по полю `icon` предмета (колба, свиток, карта существа — карточка с рамкой цвета тира и буквой вида, с душой —
  с сиянием, зеркальная — серебро; клинки, арбалет, клык, шкура, перо, пластина, осколок).
- Сумка как в MMORPG (`InventoryWindow`, кнопка «Сумка», клавиши I/B): 40 ячеек сеткой 8×5, стопки до 99 (оружие по 1),
  рамка цвета редкости (обычный серый, улучшенный зелёный, редкий синий, уникальный золотой; обычные расходники,
  трофеи — цвет типа; карты существ — цвет тира, зеркальная — серебро), «Занято N/40», «Сортировать». Касание ячейки —
  карточка (характеристики, у оружия сравнение с надетым; «Надеть», «Использовать», «Сформировать», «Продать» рядом
  с торговцем или Учителем Кирком, «Переместить», «Выбросить» с подтверждением);
  перемещение — «Переместить» и касание ячейки или перетаскиванием значка. Слева экипировка: «Оружие» рабочий
  (надетое оружие числится в сумке, но ячейку не занимает — `Inventory.equipped`), Голова/Тело/Руки/Ноги/Аксессуар —
  заглушки. Сумка полна — покупка не проходит, мешочек добычи остаётся лежать. Раскладка сохраняется в `save.json`
  (ключ `bag`); у старых сохранений её нет — предметы раскладываются по порядку сортировки. Окно торговли в том же
  стиле: товары продавца сеткой, сумка, карточка с «Купить» / «Купить ×5», продажа из ячеек сумки. Ассортимент —
  `NpcData.shop`: торговец — зелья, свиток воскрешения, оружие; Учитель Кирк — карты существ и зеркальная карта.
- Безопасные зоны (город, деревни, порт, Западный лагерь `hunter_camp` r 9, пост наёмников у пещеры `merc_post` r 4)
  из конфига острова: звери туда не заходят. Торговец и Учитель Кирк в городе.
- Жители (имена решены с Максимом; `NpcData`, ставит `Npcs.place_all` по полю `spot` через `find_spot`: проходимо,
  ровно, ≥ 3.2 м от оси дороги, не в следах построек `poi_footprints` и мелочах `poi_props`, ≥ 5 м друг от друга,
  от торговца, Кирка и точек старта, внутри своей POI (радиус − 4 м) или безопасной зоны (радиус − 1 м)):
  торговец «Торговец Гордей» (`merchant`, разговора нет — своя кнопка «Торговец»); Учитель Кирк (`kirk`);
  город — «Мудрец Альдерик» (`sage`, у ратуши, ≈ (2.3, −8.7)), «Кузнец Гуннар» (`smith`, у тренировочной площадки,
  ≈ (6.9, 5.8)), «Кладовщик Тобин» (`storekeeper`, у колодца, ≈ (−7, 4.9)); старосты у центров деревень —
  «Староста Ольвин» (`elder_human`, ≈ (86, 28.5)), «Староста Элиарна» (`elder_light`, ≈ (−84, −57)),
  «Староста Вейрис» (`elder_dark`, ≈ (76.5, −71)); «Охотница Ярра» (`hunter`, Западный лагерь `tent_w1`, севернее

  склоне — `flat` 0.8; вне логова и подступов анатем). Внешность — `CharacterModel.<id>_spec` (из примитивов, у
  каждого своя: трость, молот, посох со свитком, книга, очки, обруч, коса, лук за спиной, рваный плащ, шрам);
  заготовка под модели Meshy: `assets/characters/npc_<id>.glb` (+ `.png`) — если файл есть, он грузится вместо

  Диалог у всех общий: реплика по заданиям, иначе по положению героя (`young` / `veteran` / `kin` — своя раса или
  класс / `full_bag`), «Задания» (только у кого есть), «Торговля» (только у торговцев), пункты о делах:
  у старост «О деревне» и «Поручения деревни — скоро», кладовщик «Склад — скоро», кузнец «Кузница — скоро»,
  мудрец «Первая профессия — скоро» (Наёмник — переходная профессия, выбор пути к 12-му уровню) и «Советы
  новичку» (питомцы — к Кирку, задания, сумка, умения, безопасные места), охотница «Охота — скоро», Корвен

- Учитель Кирк (`NpcData` "kirk", `Npc`): наставник укротителей в центре города (центральная деревня), на северо-западе

## Графика: стиль аниме cel-shading (в духе Genshin Impact)
Решение Максима: стиль как у Genshin Impact. Сам стиль (cel-shading, контуры, яркие цвета) использовать можно,
чужие персонажи и ассеты — нельзя.
- Шейдеры пишем свои под Godot (toon/cel: ступенчатый свет, rim, контур). Проекты под Unity/Blender
  (GenshinCelShaderURP, Blender-miHoYo-Shaders) — только как справка по технике, код не копировать без проверки лицензии.
- Нельзя: datamined-ассеты miHoYo (например rayshire/GI_Assets), фанатские модели персонажей Genshin со Sketchfab
  и любые узнаваемые персонажи Genshin/Rappelz — это чужая интеллектуальная собственность, даже если лицензия на сайте «свободная».
- Можно: свои аниме-аватары из VRoid Studio (импорт VRM в Godot), CC0-ассеты (gobkit, Quaternius, Kenney),
  бесплатные ассеты itch.io с лицензией, разрешающей коммерческое использование (проверять каждый),
  модели из AI-генераторов (Tripo, Meshy, Hunyuan3D, hi3d, assetfurnace) по своим оригинальным эскизам — с проверкой их условий.
- Для каждого внешнего ассета записывать источник и лицензию в `assets/LICENSES.md`.
- Текстуры окружения (`assets/textures/`, 512×512) нарисовал Максим в ChatGPT листами по своим промтам; скрипт
  `tools/import_texture_sheet.py` режет лист, делает плитки бесшовными и переводит в «детальные маски»
  (`python3 -I tools/import_texture_sheet.py <лист.png> grass,dirt:0.5,...` — спецификация плиток в шапке скрипта).
  Маски почти серые, среднее 0.5, четверть цвета картинки: шейдеры умножают цвет зоны/вершины на tex × 2, палитра
  сохраняется. `tools/gen_textures.py` (прежние процедурные) пишет только недостающие файлы, `--force` затрёт
  текстуры Максима. Лицензия — `assets/LICENSES.md`.
  Что куда (повтор, м — подобран под героя 1.7 м):
  - земля `island_terrain.gdshader` (по мировым XZ, скалы triplanar): трава `grass` (3.5), дороги и площадки `dirt` (3),
    песок `sand` (4), обрывы `rock` (5), брусчатка `stone` — только площадь и улицы города (2.2, ~0.3 м на камень),
    лесная подстилка `forest` (2.5) — под деревьями: `IslandVegetation` после расстановки деревьев зовёт
    `IslandWorld.bake_forest` (сумма пятен R = 5.5 м на сетке 2 м), меш рельефа строится после растительности и пишет
    вес леса в UV2.x вершин (`IslandWorld.forest_at`); край рваный по шуму, в лесу трава не выбирается;
  - постройки `toon.gdshader` (проекция по мировым координатам, номер текстуры детали — в альфе цвета вершины
    `PoiModels.Kit`, по палитре `TEXTURE_OF` или явно `Kit.tex`): `WOOD` доски (1.8, ~0.2 м доска; стены, двери,
    настил, ящики), `MASONRY` каменная кладка `masonry` (1.6, блок ~0.5 м; все каменные цвета палитры — цоколи,
    колодцы, стены тёмных эльфов, башни, маяк, трубы, ступени), `PLASTER` (3), `TILES` черепица (1.3, ряд ~0.3 м),
    `THATCH` солома (1.5), `ROCK` (3), кора `bark` (1.0): `BARK` — стоячие брёвна (столбики оград
    `PoiModels.fence_post`, сваи и тумбы причала, столбики перил моста, шесты, поленья костра), `LOG` — лежачие
    (жерди оград `fence_rails`, поручни моста, ворот колодца, скамейки у костра; волокна вдоль бревна).
    Брусчатка у построек не используется. Стволы деревьев (`IslandVegetation`, StandardMaterial по цветам вершин)
    без текстуры — ради производительности.
  - Сэмплеров у `toon.gdshader` 8 (albedo + 7) — предел: GL Compatibility Godot 4.3 держит верхние 8 текстурных
    блоков (тени, небо, отражения, экран), а у многих телефонов их 16. Новая текстура построек — только вместо
    старой или через Texture2DArray; у земли сейчас 6.
  Включены на «Среднем» и «Высоком» (ключ `textures` в `Quality.PRESETS`), на «Низком» выборок нет (и подстилки нет).

## Проверка и сборка
- Автотест локально: `godot --headless --path . --import`, затем
  `godot --headless --fixed-fps 60 --path . res://tests/runner.tscn -- res://tests/smoke_test.gd`
  (каждый тест должен вывести `TEST OK`).
  Godot в облачной сессии Claude запускать не разрешено — проверка идёт в CI (workflow «Проверка кода»).
- APK (только по команде Максима): GitHub → Actions → «Сборка APK» → Run workflow с версией,
  или `git tag v0.1.1 && git push origin v0.1.1`, или новая версия в `android/release_version.txt`. Готовый APK появляется в Releases (тег `v<версия>`).
  Для каждой новой сборки — новая версия/тег.
- Свой ключ подписи: секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_USER`, `ANDROID_KEYSTORE_PASSWORD`.
  Внимание: APK с другим ключом не встанет поверх старого, нужно удалить прежнюю версию.

## План

2. Графика в стиле аниме cel-shading (готово, версия 0.3.0; модели из примитивов, позже можно заменить на VRoid).

## План: профессии (реализация — позже)
- Герой любой расы стартует **Бродягой** (`wanderer`): без умений, JP копятся. С 10 ур. — задание на первую
  профессию (у мудреца Альдерика), в конце выбор одной из трёх профессий своей расы. Задание можно пройти позже,
  до 20 ур.: **сверх-эволюция** — при смене профессии +5 JP за каждый уровень выше 10 (решение Максима; потолок +50 JP на 20 ур.;
  по мотивам overbreed питомцев вики). Требования умений — ур. = 10 + JLv вики × 0.75 (решение Максима: умения профессии
  полностью открываются к 40 ур.; максимальный JLv 1-й профессии на вики — 40).
- Профессии (наше ← вики): Светлые эльфы — Мечник ← Holy Warrior, Волшебник ← Cleric, Зверолов ← Breeder;
  Тёмные эльфы — Наёмник ← Strider (есть), Неофит ← Dark Magician, Адепт ← Sorcerer;
  Люди — Воин ← Fighter, Шаман ← Kahuna, Колдун ← Spell Singer (призыватель существ); Адепт — тоже призыватель, Неофит — маг («Следопыт» — для 2-й профессии лучника).
- Справочник: `tools/rappelz_jobs_reference.md` (умения каждой профессии: id, названия, тип, оружие, JLv, суть, где
  значок; общие умения разных профессий — один id и один значок; 6 умений Наёмника переиспользуются). Промты значков
  (156 новых, 12 листов для `tools/cut_icon_sheet.py`) — `tools/Промты_значки_умений_профессий.docx`.
